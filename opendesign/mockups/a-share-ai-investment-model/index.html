今天怎么用这一套系统

Daily routine
1. 更新股票池

去“系统股票池”点更新，系统从全 A 股里筛出最多 30 只强势候选。

2. 看推荐原因

先看评分、动作、风险标记，不要只看涨幅或排名。

3. 对照持仓

去“个人持股”看哪些要降仓，避免新买和旧仓风险叠加。

4. 做人工复核

检查公告、涨跌停、成交额、行业拥挤度，确认不是单日情绪。

5. 形成计划

只输出明天的观察、加仓、减仓清单；不自动下单。

评分系统对强势程度、成交活跃度、日内位置和风险惩罚后的综合排序。

6. 交易复盘记录建议、采纳、盈亏、失效原因，反向校准模型。已有 advice_log 设计；下一步把网页操作写入日志。

优化后的评分逻辑

Quality-first
universe = all_a_share_spot()
  .exclude(ST, delisting, low_price)
  .where(amount >= 3e8)

quality_score =
  0.25 * strength_score          # 有上涨强度，但过热扣分
  0.25 * liquidity_score         # 成交额足，便于进出
  0.20 * close_position_score    # 收盘接近日内高位
  0.15 * tradability_score       # 涨停/接近涨停扣分
  0.10 * stability_score         # 振幅过大扣分
  0.05 * gap_quality_score       # 跳空过大扣分

action = "buy" only if:
  quality_score >= 78
  and 1% < pct_change < 9.7%
  and close_position >= 55%
  and intraday_amplitude <= 12%

final_pool = rank(quality_score)
  .with_reason()
  .with_risk_flags()
  .top(30)

为什么这样优化

Institutional habits
问题机构常见处理本系统改动
涨停股霸榜但买不到把可交易性和冲击成本纳入模型。新增 tradability_score，接近涨停会降权。
只看涨幅容易追高把收益信号和风险信号分开建模。强势分会因过热、振幅、跳空被扣分。
高波动票胜率不稳定用波动、振幅、流动性做风险门禁。新增 stability_score 和 high_intraday_amplitude 风险标记。
因子可能只在某段行情有效长期用 IC/RankIC、分组收益和 walk-forward 验证。下一步把回测模块接入每个因子的保留/剔除决策。
